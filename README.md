# Argent Skill Atlas

An interactive map of every conditional branch in the argent skill corpus
(`packages/skills/skills/` — 16 `SKILL.md` files, 1,882 lines), grouped by the
file each branch lives in and wired by the references between files.

Each of the **216 conditionals** is one node, tagged by branch kind and carrying
an `L<n>` button that opens that exact line on GitHub. The **54 references**
between skills are drawn as arrows, anchored to the specific conditional that
makes the reference rather than to the file as a whole.

## Quick start

```bash
scripts/build.sh          # data/ + src/ -> dist/index.html
scripts/serve.sh          # http://localhost:8099
```

`dist/index.html` is fully standalone — you can also just open it directly
(`open dist/index.html`) with no server. The only network dependency is the
Google Fonts stylesheet; without it the page falls back to system fonts.

```bash
node scripts/verify.mjs            # re-prove the atlas against the argent repo
node scripts/verify.mjs --report   # also write dist/alignment.txt
```

## The pinned ref — read this before trusting a line number

Every source link points at commit **`b835de23`**, not `main`:

```
https://github.com/software-mansion/argent/blob/b835de23…/packages/skills/skills/<file>/SKILL.md#L<line>
```

The atlas was built by reading the skills at that commit, so the line anchors are
exact against it and would silently rot against a moving branch. `b835de23` is on
`origin/main`, so the permalinks resolve.

**The tradeoff:** this is a snapshot. At the time of writing, `origin/main` was
already 18 commits ahead, 4 of them touching skills — physical-iOS support
(#944, #1031) and flow script steps (#865, #940). Those changes are *not*
reflected here. The repo is private, so the links need a GitHub session.

`scripts/verify.mjs` is what keeps this honest: it checks every anchor against
the committed blob at the pinned ref, so a stale claim fails loudly instead of
producing a link that quietly points at the wrong line.

## Re-pointing at a newer commit

The ref lives in one place, `data/source.json`. Moving it is a data edit — but
moving it alone is **not** enough, because the line numbers were derived by
reading the files. The honest sequence:

1. `git -C ~/dev/argent fetch origin && git -C ~/dev/argent log --oneline <old>..origin/main -- packages/skills/skills`
2. Read whatever changed. Update `src/atlas.html` if branches were added, removed
   or reworded, and fix the affected entries in `data/lines.json`.
3. Set the new `ref` / `refShort` in `data/source.json`.
4. `scripts/build.sh && node scripts/verify.mjs` — check 2 catches every anchor
   that the new commit moved, and check 3 catches every reference that appeared
   or disappeared.

Step 4 will not pass until steps 1-3 are actually done, which is the point.

## Layout

```
src/atlas.html      the page: markup, styles, graph data, force layout, interactions.
                    Authored in Claude-Artifact form (no <!doctype>/<head> wrapper) with
                    __SOURCE__ / __LINES__ placeholders where data gets injected.
data/source.json    repo URL, pinned ref, path to the skills dir, local checkout
data/lines.json     216 node id -> line number in its SKILL.md
scripts/build.sh    wraps src/ into a standalone document, injects data/
scripts/verify.mjs  re-proves the atlas against the argent repo at the pinned ref
scripts/serve.sh    serves dist/ on 127.0.0.1 (dist only, never the project root)
dist/index.html     built output
dist/alignment.txt  generated by --report: every conditional beside its source line
```

`src/atlas.html` is the only hand-edited file; `dist/` is generated and safe to
delete. The line map and the ref were deliberately pulled out into `data/` so
they exist exactly once — an earlier draft kept a second copy inline and the two
could drift.

## Using the map

| Action | Result |
| --- | --- |
| Click a condition row | Opens that branch's body (collapsed by default — the bodies are long) |
| Click `L<n>` | Opens that line on GitHub in a new tab |
| Click a module title | Focuses that skill: unrelated cards dim, its edges light up |
| Click a legend chip | Filters by branch kind |
| Search | Filters across condition text and bodies, highlighting hits |
| Drag header / drag board / scroll | Move a module, pan, zoom |
| `Esc` | Clear focus |

### Branch kinds

Derived from the corpus rather than imposed on it:

| Kind | n | What it marks |
| --- | ---: | --- |
| choice | 67 | Pick the right tool, evidence or query for the case |
| failure | 39 | An error path and its recovery |
| platform | 29 | Forks on iOS / Android / Chromium / Vega / TV |
| gate | 26 | A hard capability, support or safety gate |
| state | 25 | Forks on device, server or session state |

## How verification works

`verify.mjs` reads the graph out of `src/atlas.html` and checks it against
`git show <ref>:<path>` in a local argent checkout — the **committed blobs**, not
a working tree, so an uncommitted local edit can never make a check pass.

1. **Structure** — node ids unique, every `refs` target resolvable, branch kinds
   declared, and each skill's stated line count matching its blob.
2. **Line anchors** — all 216 present, in range, and landing on a non-blank line
   at the pinned commit.
3. **Edges** — independently re-derives the reference set by grepping every
   `.md` under the skills path at that commit, then diffs it against what the
   atlas draws, in both directions. Neither an invented edge nor a missed one
   passes.

Point it at a different checkout with `--checkout <path>`.

The verifier is mutation-tested: pointing a node at a blank line, past EOF,
dropping it from the map, inventing an edge, deleting a real one, and naming an
unresolvable ref target are each caught by the check that should catch them.

## Two things the map surfaced

- **`argent-lens` has zero inbound references.** Nothing in the corpus routes to
  it — it is reachable only if the user names it or the feature flag is on.
  Every other skill is reachable from at least one other.
- **`argent-device-interact` (10 inbound) and `argent-create-flow` (6) are the
  hubs.** A convention change propagates from those two, so they are where a
  contradiction does the most damage.

One edge is file-level rather than conditional-level:
`argent-react-native-profiler → argent-react-native-optimization` states
"complementary, not a replacement" in prose, not in a branch, so it anchors to
the card header instead of to a node.
